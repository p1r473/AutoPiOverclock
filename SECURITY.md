# Security policy

Do not include private hostnames, addresses, SSH configuration, service names, media paths, logs, or credentials in issues or fixtures. `report TARGET --redact` creates a target-neutral filename, substitutes known target/controller identifiers, and omits free-form diagnostic reasons and storage details. Treat that file as a safer starting point, not an automatic publication guarantee: inspect it before sharing and never publish raw run artifacts. Reports generated by older releases are not retroactively renamed or sanitized.

Treat command-injection, unsafe configuration evaluation, path traversal, privilege-boundary errors, backup/rollback failures, and redaction failures as security issues.

Report vulnerabilities privately through **Security → Advisories → Report a vulnerability** in the GitHub repository. If private vulnerability reporting is temporarily unavailable, open a minimal issue requesting a private contact channel without including exploit details, target information, logs, or other sensitive data.
