# Output and classifications

All artifacts are flat under `--output-dir` (`$HOME/overclock-results` by default); no per-target directories are created and existing runs are never deleted. Prepare, overclock, and manual test operations record their effective `.conf`, discovery snapshot, atomic `.state`, `.log`, `.csv`, `.jsonl`/`.json`, and summary; overclock and test also record per-candidate logs. A reset records its own atomic state and audit output without manufacturing a tuning configuration or candidate logs. The `*-latest.log`, `*-latest-summary.txt`, `*-latest.state`, and `*-latest.json` links select the latest retained operation for a target.

`reset` creates a separate audit run instead of reusing or deleting tuning history. Previous run files remain byte-preserved even when the target's `*-latest` links advance to the reset audit. A successful reset state ends at `COMPLETE/STOCK_VERIFIED` and records the verified pre-reset hash, post-reset hash, persistent remote config-backup path, and disabled-key evidence. When attributable project tryboot evidence required cleanup, its backup path is recorded separately. The final `reset` PASS event reports that a new permanent-config boot reached verified firmware stock defaults and that prior logs and saved runs were preserved.

| Classification | Meaning |
|---|---|
| `PREFLIGHT_FAILURE` | Unsupported/missing prerequisite before tuning. |
| `HARNESS_FAILURE` | The intended test did not actually run or prove its workload, including an unstructured same-boot transport loss. |
| `BOOT_FAILURE` | Candidate boot or required display/audio/service health failed. |
| `STABILITY_FAILURE` | Power, temperature, kernel, GPU, storage, filesystem, or stress failure, including a proven autonomous candidate reboot during active stress. |
| `RECOVERY_FAILURE` | The target did not return to verified permanent normal configuration. |
| `APPLY_FAILURE` | Permanent application or rollback failed. |

The `.state` file is data-only: sorted uppercase keys with base64-encoded values. It is never sourced. The `.jsonl` event stream is finalized into a JSON array when the controller exits.

Clock results are intentionally separate: `PASSED_CPUS`/`PASSED_GPUS` record observed sweep/refinement passes; `CPU_FAILURE_BOUNDARY`/`GPU_FAILURE_BOUNDARY` retain the first refined edge; `CPU_GUARD_TARGET`/`GPU_GUARD_TARGET` record tested production guards; and `FINAL_CPU`/`FINAL_GPU` remain empty until full validation completes. `CPU_QUALIFICATION_*` binds the two-hour CPU-only result to its exact clock and stock GPU, while `GPU_QUALIFICATION_*` binds the two-hour GPU-only result to its exact qualified CPU/GPU pair. `FINAL_BACKOFF_COUNT`, `FINAL_BACKOFF_CPU`, `FINAL_BACKOFF_GPU`, and the ordered `FINAL_BACKOFF_HISTORY` bind recovered qualification/final boundaries to monotonically reduced validation targets. History entries are `CPU:FROM>TO`, `GPU:FROM>TO`, or `PAIR:CPU_FROM/GPU_FROM>CPU_TO/GPU_TO`. `PAIR` means combined validation proved the pair failed but did not identify one causal domain, so each still-overclocked domain received its configured production guard before both qualifications restarted. Optional edge mode additionally records `FLOOR_*` evidence and `EDGE_CPU_*` status so a recovered edge rejection can retain the validated floor without being confused with an edge pass.

`RUN_SCHEMA` prevents an older interrupted state from bypassing newer resume gates. `AUTO_BASELINE_*` preserves the immutable stock tuple and provenance even after a successful apply updates the live normal clocks. `CANDIDATE_LABEL`, candidate clocks, and `CANDIDATE_STAGE` identify the exact recoverable candidate substage. `FINAL_TARGET_CPU`, `FINAL_TARGET_GPU`, and `FINAL_STAGE` do the same for final validation. `VALIDATION_SCHEMA` and `VALIDATION_DURATION_S` are recorded only when final validation completes and are both required by `apply`; an optional edge pass must carry 86,400 seconds rather than the ordinary 28,800-second floor.

A later edge run sets `POST_FLOOR_EDGE=1` and binds `SOURCE_FLOOR_RUN_ID` plus `SOURCE_FLOOR_PERMANENT_HASH` to its retained source. Its own run ID keeps apply and rollback artifacts separate, while `MODE_EFFECTIVE` and `REQUIRE_GPU_STRESS` preserve the proven graphical or headless path. `CFG_MAX_FAN` records whether candidate tryboots use the default maximum-cooling block (`1`) or the explicit `--no-max-fan` policy (`0`); status, report, summary, and effective-config comments expose that choice, and resume retains it.

A manual exact-clock record has `ORIGIN_COMMAND=test`, `MANUAL_TEST=1`, `MANUAL_CPU`, `MANUAL_GPU`, `MANUAL_MINUTES`, `MANUAL_DURATION_S`, and a `MANUAL_TEST_STATUS` of `READY`, `RUNNING`, `PASS`, or `FAILED`. A pass deliberately retains `VALIDATED=0`, empty validation-schema/endurance fields, and `APPLY_STATUS=NOT_APPLIED`; it is evidence for that explicit test condition, not an application candidate. `RUN_MAX_TEMP` retains the highest structured worker temperature seen across the run.

`PROGRESS_ACTIVE_SECONDS` checkpoints active controller time across safe continuation. `PROGRESS_STRESS_*` records the current timed workload and its latest worker elapsed/duration counters, while `PROGRESS_LAST_*` caches clocks, temperature, throttle, and fan telemetry for display. `RECOVERY_WAIT_*` records when an unattended public overclock exceeded its ordinary SSH budget and entered extended read-only monitoring. These fields support operator visibility; they do not replace raw evidence. Every worker line, including telemetry with `elapsed=SECONDS/TOTALs`, remains in the per-attempt and main logs. Noninteractive output also prints those raw lines directly. A signal clears and disables only the advisory display while the exit trap continues to log required recovery evidence.

Graphical runs store `DISPLAY_BASELINE` and the discovered `AUDIO_BASELINE`, and both identities are required on subsequent candidate, normal-recovery, and apply health checks. Debian prefers an active PipeWire/PulseAudio default-sink identity and otherwise records the sorted complete ALSA playback inventory, so a missing desktop audio session does not disable audio validation or force the controller to guess one device. A configured `audio_sink_pattern` still requires a matching desktop sink. Batocera graphical runs require its active default-sink identity. Headless Debian-family runs intentionally retain empty display/audio baselines and instead record `DRM_RENDER_NODE` plus `STRESS_NG_GPU_STRATEGY`; the strategy is either exact V3D-device selection or the verified single-V3D-node fallback. Discovery also records `FAN_PWM_STATUS`; with default maximum cooling, candidate health and every stress telemetry sample report PWM/RPM proof when Linux exposes the Pi `pwmfan` device. `--no-max-fan` records the normal policy without making a PWM-255 claim. `not-detected` is retained as an honest absence of software fan evidence, not reported as 100%. Watchdog discovery records the EEPROM timeout, active kernel handoff, device, live timeout, and owner. A Debian repair additionally records its status, old/expected/new hashes, and backup path so an interrupted `PREPARE` report does not conceal a partial change.

Interrupted apply state records `APPLY_OLD_HASH`, `APPLY_EXPECTED_HASH`, a deterministic `APPLY_BACKUP`, boot evidence, and the intended recovery action. Reconciliation accepts only the known old or proposed hash; an unknown permanent hash is left untouched for manual recovery.
